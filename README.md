# Med System

Настольное приложение для автоматизации работы медицинского пункта колледжа.
Предназначено для локального учёта обращений, сотрудников, студентов,
лекарственных средств и связанных медицинских сроков.

Приложение работает без подключения к внешним сервисам и хранит данные в
локальной базе SQLite.

## Возможности

- ведение карточек сотрудников и студентов;
- контроль сроков санминимума, медицинского осмотра и флюорографии;
- управление учебными группами и перевод групп на следующий курс;
- восстановление удалённых записей из корзины;
- учёт лекарств, остатков и сроков годности;
- формирование списка лекарств для заказа;
- журнал обращений с жалобами, диагнозом и рекомендациями;
- поиск по встроенному справочнику МКБ-10.

## Системные требования

- Windows 10 версии 1809 (build 17763) или новее;
- архитектура x64 или x86 для готового пакета из GitHub Releases;
- права администратора для первоначальной установки самоподписанного
  сертификата.

Готовый MSIX-пакет является self-contained: отдельная установка .NET 8 на
целевой компьютер не требуется.

## Структура проекта

```text
MedSystem/
├── MedSystem.App/     интерфейс WinUI 3, страницы, формы и MSIX-манифест
├── MedSystem.Core/    модели, валидация и правила контроля сроков
├── MedSystem.Data/    подключение к SQLite, репозитории и создание схемы
└── MedSystem.slnx     решение Visual Studio
```

`MedSystem.App` использует `MedSystem.Core` и `MedSystem.Data`, а слой данных
зависит от `MedSystem.Core`. Windows-специфичный код расположен в проекте
`MedSystem.App`.

## База данных

Все рабочие данные находятся в файле `med_system.db`. При запуске
установленного MSIX-приложения используется каталог данных текущего
пользователя:

```text
%LOCALAPPDATA%\Packages\<PackageFamilyName>\LocalState\med_system.db
```

База создаётся автоматически при первом запуске. Инициализатор создаёт
отсутствующие таблицы и добавляет начальный набор кодов МКБ-10. Внешние ключи
SQLite включаются для каждого соединения.

Основные таблицы:

- `employees` — сотрудники;
- `students` и `groups` — студенты и учебные группы;
- `medicines` — лекарства, количество и сроки годности;
- `appeals` — журнал обращений;
- `icd_codes` — справочник МКБ-10;
- `system_info` — служебные данные.

Схема совместима с исходной Python-версией
[`med-system`](https://github.com/ZentifyID/med-system). Отдельного механизма
миграций в текущей версии нет.

### Резервное копирование и перенос данных

Приложение автоматически создаёт резервную копию не чаще одного раза в сутки и
хранит последние 10 автоматических копий в каталоге `Backups` рядом с рабочей
базой. В разделе **Настройки → Резервные копии** можно сохранить копию в
выбранное защищённое место или восстановить базу из ранее созданной копии.

Перед восстановлением приложение проверяет целостность выбранного файла и
создаёт страховочную копию текущей базы. После восстановления приложение нужно
запустить заново.

Перед ручным копированием файла `med_system.db` через Проводник приложение
должно быть закрыто.

### Корзина

Удаление студентов, сотрудников, лекарств, обращений и пустых групп переносит
записи в корзину. Оттуда запись можно восстановить или удалить окончательно.
По умолчанию корзина автоматически очищает записи через 60 дней. Срок можно
изменить от 1 до 365 дней в настройках или полностью отключить автоочистку.

Группу со студентами нельзя переместить в корзину: сначала студентов нужно
перевести в другую группу. Это защищает связанные записи от каскадного
удаления.

### Архив

Студентов и сотрудников можно архивировать с указанием причины, а затем
просматривать через переключатель **Активные / Архив** и восстанавливать.
Операция **Завершить обучение** архивирует группу и всех её активных студентов
одной транзакцией. При восстановлении группы возвращаются только студенты,
архивированные одновременно с ней; ранее архивированные отдельно записи не
затрагиваются.

Для переноса данных на другой компьютер:

1. Установить и один раз запустить приложение на новом компьютере.
2. Закрыть приложение.
3. Заменить созданный файл `med_system.db` сохранённой копией в каталоге
   `LocalState`.

Имя каталога пакета можно определить командой:

```powershell
Get-AppxPackage *MedSystem* | Select-Object Name, PackageFamilyName
```

База может содержать персональные и медицинские сведения. Такие файлы не
должны добавляться в репозиторий или прикладываться к публичным релизам.

## Установка готовой версии

1. Скачать ZIP-архив последней версии на странице **Releases**.
2. Полностью распаковать архив.
3. Запустить `Install.ps1` или `Add-AppDevPackage.ps1` через пункт
   **«Выполнить с помощью PowerShell»**.
4. Подтвердить установку сертификата и пакета.
5. Запустить **MedSystem.App** из меню «Пуск».

Если политика выполнения блокирует скрипт, PowerShell следует открыть от имени
администратора в распакованном каталоге и выполнить:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\Install.ps1
```

Изменение политики действует только в текущем окне PowerShell.

### Ручная установка

1. Открыть файл `.cer` и выбрать **«Установить сертификат»**.
2. Выбрать хранилище **«Локальный компьютер»**.
3. Поместить сертификат в **«Доверенные лица»** (`Trusted People`).
4. Открыть `.msixbundle` и нажать **«Установить»**.

Самоподписанный сертификат следует устанавливать только для пакета,
полученного из доверенного релиза этого репозитория.

## Обновление

Новая версия устанавливается поверх существующей. Удалять предыдущую версию
перед обновлением не требуется: данные в `LocalState` сохраняются.

Для корректного обновления пакет должен иметь увеличенный номер версии,
прежние идентификаторы пакета и того же издателя. Выпуски рекомендуется
подписывать тем же сертификатом, пока он действует.

## Сборка из исходников

Требуется Visual Studio 2022 с рабочей нагрузкой **«Разработка приложений для
Windows»** и компонентами Windows App SDK.

1. Открыть `MedSystem/MedSystem.slnx`.
2. Выбрать `Debug` или `Release` и нужную архитектуру.
3. Собрать решение или запустить проект `MedSystem.App`.

Сборка из командной строки:

```powershell
dotnet build MedSystem/MedSystem.slnx -c Release -p:Platform=x64
```

## Создание установочного пакета

В Visual Studio:

1. Открыть контекстное меню проекта `MedSystem.App`.
2. Выбрать **Package and Publish → Create App Packages**.
3. Выбрать распространение вне Microsoft Store (`Sideloading`).
4. Выбрать существующий сертификат подписи или создать тестовый.
5. Выбрать конфигурацию `Release` и необходимые архитектуры.
6. Создать пакет.

Результат появляется в каталоге
`MedSystem/MedSystem.App/AppPackages/MedSystem.App_<версия>_Test`. Для
распространения архивируется весь каталог: `.msixbundle`, публичный `.cer`,
установочные скрипты и зависимости, если они были созданы.

Файл `.pfx` содержит закрытый ключ подписи и не должен публиковаться,
передаваться пользователям или добавляться в Git.
