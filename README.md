# Med System

Локальное настольное приложение для работы медицинского пункта колледжа.
Помогает вести студентов, сотрудников, обращения и лекарственные средства без
внешнего сервера и подключения к интернету.

Данные хранятся в SQLite на компьютере пользователя. Приложение рассчитано на
одного оператора и десятки тысяч записей.

## Возможности

### Учёт

- карточки студентов и сотрудников с медицинскими сроками;
- учебные группы, ежегодный перевод на следующий курс и архив выпускников;
- журнал обращений с жалобами, диагнозом и рекомендациями;
- учёт лекарств, остатков, сроков годности и формирование заказа;
- редактируемый справочник МКБ-10;
- предупреждение о возможных дублях людей при сохранении.

### Работа с большим объёмом данных

- поиск выполняется SQL-запросами, а не фильтрацией всего списка в памяти;
- студенты, сотрудники, лекарства, обращения, МКБ и корзина загружаются
  страницами по 100 записей;
- длительные чтения выполняются в фоне, интерфейс показывает индикатор загрузки;
- индексы SQLite ускоряют основные фильтры, сортировку и переход по страницам.

### Надёжность данных

- удалённые записи сначала попадают в корзину;
- срок хранения в корзине настраивается от 1 до 365 дней, автоочистку можно
  отключить;
- студентов, сотрудников и учебные группы можно архивировать с указанием
  причины;
- автоматическая резервная копия создаётся не чаще одного раза в сутки,
  сохраняются последние 10 копий;
- перед восстановлением проверяется целостность выбранной базы и создаётся
  страховочная копия текущих данных;
- схема базы обновляется встроенными версионированными миграциями.

## Системные требования

- Windows 10 версии 1809 (build 17763) или новее;
- x64 или x86 для готового пакета из GitHub Releases;
- права администратора для первоначальной установки самоподписанного
  сертификата.

Готовый MSIX-пакет является self-contained: отдельно устанавливать .NET 8 на
рабочий компьютер не требуется.

## Архитектура

```text
MedSystem/
├── MedSystem.App/     WinUI 3: окна, страницы, формы и MSIX
├── MedSystem.Core/    модели, валидация и правила контроля сроков
├── MedSystem.Data/    SQLite, миграции, резервные копии и репозитории
└── MedSystem.slnx     решение Visual Studio
```

Зависимости направлены от интерфейса к данным и предметной области:

```text
MedSystem.App ──► MedSystem.Data ──► MedSystem.Core
        └──────────────────────────► MedSystem.Core
```

SQL-параметры используются для пользовательских значений. Операции, которые
изменяют несколько связанных записей, выполняются в транзакциях.

## База данных и резервные копии

Рабочая база называется `med_system.db`. В установленном MSIX-приложении она
находится в каталоге данных текущего пользователя:

```text
%LOCALAPPDATA%\Packages\<PackageFamilyName>\LocalState\med_system.db
```

При первом запуске приложение создаёт таблицы, индексы и начальный справочник
МКБ-10. При следующих запусках недостающие изменения схемы применяются
автоматически. Внешние ключи SQLite включаются для каждого соединения.

Автоматические копии находятся в подкаталоге `Backups` рядом с рабочей базой.
Ручное создание и восстановление копии доступно в разделе
**Настройки → Резервные копии**. После восстановления приложение закрывается —
его нужно запустить заново.

Для ручного копирования `med_system.db` через Проводник сначала закройте
приложение. Для переноса на другой компьютер безопаснее использовать встроенное
создание и восстановление резервной копии.

> База содержит персональные и медицинские сведения. Не добавляйте файлы
> `.db`, резервные копии и реальные данные в Git или публичные релизы.

## Установка готовой версии

1. Скачайте ZIP-архив последней версии на странице **Releases**.
2. Полностью распакуйте архив.
3. Запустите `Install.ps1` или `Add-AppDevPackage.ps1` через пункт
   **«Выполнить с помощью PowerShell»**.
4. Подтвердите установку сертификата и пакета.
5. Запустите **MedSystem.App** из меню «Пуск».

Если политика выполнения блокирует скрипт, откройте PowerShell от имени
администратора в распакованном каталоге и выполните:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\Install.ps1
```

Изменение политики действует только в текущем окне PowerShell.

### Ручная установка

1. Откройте файл `.cer` и выберите **«Установить сертификат»**.
2. Выберите хранилище **«Локальный компьютер»**.
3. Поместите сертификат в **«Доверенные лица»** (`Trusted People`).
4. Откройте `.msixbundle` и нажмите **«Установить»**.

Устанавливайте самоподписанный сертификат только из доверенного релиза этого
репозитория.

## Сборка из исходников

Понадобятся Visual Studio 2022, рабочая нагрузка **«Разработка приложений для
Windows»**, .NET 8 SDK и компоненты Windows App SDK.

1. Откройте `MedSystem/MedSystem.slnx`.
2. Выберите конфигурацию `Debug` или `Release` и нужную архитектуру.
3. Соберите решение или запустите проект `MedSystem.App`.

Проверочная сборка без сертификата подписи:

```powershell
dotnet build MedSystem/MedSystem.slnx -c Release -p:Platform=x64 -p:AppxPackageSigningEnabled=false
```

Дополнительные проверки перед коммитом или релизом:

```powershell
dotnet format MedSystem/MedSystem.slnx --verify-no-changes --no-restore
dotnet list MedSystem/MedSystem.slnx package --vulnerable --include-transitive
```

## Создание установочного пакета

В Visual Studio:

1. Откройте контекстное меню проекта `MedSystem.App`.
2. Выберите **Package and Publish → Create App Packages**.
3. Выберите распространение вне Microsoft Store (`Sideloading`).
4. Выберите существующий сертификат подписи или создайте тестовый.
5. Выберите `Release` и архитектуры x86/x64.
6. Создайте пакет.

Результат появится в каталоге
`MedSystem/MedSystem.App/AppPackages/MedSystem.App_<версия>_Test`. В релизный ZIP
нужно положить весь созданный каталог: `.msixbundle`, публичный `.cer`,
установочные скрипты и зависимости, если они были созданы.

Файл `.pfx` содержит закрытый ключ подписи. Его нельзя публиковать, передавать
пользователям или добавлять в Git.

## Обновление приложения

Новая версия устанавливается поверх предыдущей, а данные в `LocalState`
сохраняются. Для корректного обновления необходимо увеличить версию пакета и
сохранить прежние `Identity Name`, `Publisher` и сертификат подписи.

## Текущие ограничения

- приложение рассчитано на локальную работу на одном компьютере;
- сетевой режим и одновременная работа нескольких пользователей не
  поддерживаются;
- импорт и экспорт таблиц пока не реализованы;
- автоматические UI-тесты пока отсутствуют, поэтому перед релизом дополнительно
  проверяются запуск, основные формы, корзина и восстановление резервной копии.
